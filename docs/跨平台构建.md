# 跨平台构建指南

Magic Photo 的界面与绘制逻辑全部在一个自包含的 `index.html` 中，各平台只是不同的离线 WebView 外壳。

| 平台 | 外壳 | 保存方式 | 状态 |
| --- | --- | --- | --- |
| Windows 10/11 x64 | Tauri 2 + WebView2 | 系统保存对话框 | 已验证，提供成品 |
| macOS 10.15+ | Tauri 2 + WKWebView | 系统保存对话框 | 配置完成，需在 macOS 构建 |
| Linux x64 | Tauri 2 + WebKitGTK 4.1 | 系统保存对话框（XDG Portal / GTK） | 配置完成，需在 Linux 构建 |
| Android 7.0+ | Tauri 2 + Android System WebView | Storage Access Framework 保存对话框 | 已构建可安装 APK，真机交互待验证 |
| iOS 15+ | Tauri 2 + WKWebView | 系统文档选择器 | 配置完成，需在 macOS/Xcode 构建 |
| OpenHarmony 5.0+ | ArkTS Web 组件 | 系统文档选择器（JS Bridge） | 实验性，需 DevEco Studio |

所有版本共用同一份页面和同一套 CSP。照片只在内存中处理，应用不申请网络权限，也不发起网络请求。

## 通用准备

- Node.js 20 或更新版本
- Rust stable（桌面端需要 MSVC / Xcode / GCC 工具链）
- 先执行 `npm install`

```bash
npm run prepare-dist   # 生成 dist/index.html（内联全部 CSS）
npm run offline-html   # 同上，生成单文件离线网页
```

## Windows

要求：Visual Studio Build Tools（Desktop development with C++）、WebView2 Runtime。

```bash
npm run package          # 安装包 + 便携版 + 离线网页，统一放到 release/
npm run build            # 只构建 NSIS 安装包
npm run build:portable   # 只构建免安装 exe
```

产物：`src-tauri/target/release/magic-photo.exe`、`src-tauri/target/release/bundle/nsis/*.exe`。

## macOS

要求：macOS 10.15+、Xcode Command Line Tools（`xcode-select --install`）。

```bash
npm run build
```

产物为 `src-tauri/target/release/bundle/macos/Magic Photo.app` 与 `bundle/dmg/*.dmg`。没有 Apple Developer 签名时，首次打开需右键选择“打开”，或执行：

```bash
xattr -cr "/Applications/Magic Photo.app"
```

如要分发，请配置 Apple Developer ID 并使用 Tauri 的签名/公证配置。

## Linux

以 Ubuntu/Debian 为例，先安装 Tauri 2 与 WebKitGTK 依赖：

```bash
sudo apt update
sudo apt install -y libwebkit2gtk-4.1-dev build-essential curl wget file \
  libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev \
  libgtk-3-dev
```

然后：

```bash
npm run build
```

产物为 `src-tauri/target/release/bundle/deb/*.deb` 与 `bundle/appimage/*.AppImage`。若使用 Wayland，原生保存对话框通过桌面 portal 工作；没有 portal 的极简环境可能回退到 GTK。

## Android

要求：

- JDK 17（`JAVA_HOME` 指向 JDK 17，Android Gradle Plugin 不支持 JDK 8）
- Android SDK Platform 37、Build Tools 37.0.0
- Android NDK `29.0.13846066`
- Rust 目标：`aarch64-linux-android`、`armv7-linux-androideabi`、`i686-linux-android`、`x86_64-linux-android`

```bash
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
npm run android:init     # 仅在需要重新生成工程时执行；src-tauri/gen/android 已随仓库提供
npm run android:build -- --apk --debug --target aarch64
```

`JAVA_HOME`、`ANDROID_HOME`、`NDK_HOME` 必须指向正确目录。如果 Gradle 报 `Cannot convert URI 'file:///...'` 之类的仓库错误，通常是 `%USERPROFILE%\.gradle\init.d` 里的全局脚本与 Gradle 9 不兼容；可以临时把 `GRADLE_USER_HOME` 指向一个干净目录，或修正该全局脚本。

调试 APK 通常位于：

```
src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
```

调试构建使用 Android 调试证书，可直接安装测试，但体积较大且不适合上架。正式发布前在 Android Studio 打开 `src-tauri/gen/android` 配置签名，再执行不带 `--debug` 的构建。仓库 [`release/`](../release/) 中的 Android APK 是 release 构建后用本机调试证书签名，同样只适合直接安装测试。调试运行：

```bash
npm run android:dev
```

移动端的“下载海报”会调用系统的“另存为”界面（SAF），不需要申请存储权限。可从相册/文件选择照片，照片仍然只在 WebView 内存中处理。

## iOS

要求：macOS、Xcode 15+、CocoaPods。

```bash
rustup target add aarch64-apple-ios x86_64-apple-ios aarch64-apple-ios-sim
npm run ios:init
npm run ios:build
```

使用 Xcode 打开 `src-tauri/gen/apple/*.xcodeproj` 配置开发团队与签名。没有 Apple 开发者证书时，CI 只能构建模拟器版本（例如 Apple Silicon 模拟器）：

```bash
npx tauri ios build --target aarch64-sim --ci
```

真机安装或发布 IPA 必须配置 Apple 签名，Tauri CLI 目前没有 `--no-sign` 构建真机包的方式。iOS 端同样使用系统文档选择器保存 PNG，不需要相册写入权限；`src-tauri/Info.ios.plist` 已包含相册与相机的用途说明，便于系统文件选择器读取本地照片。

## OpenHarmony（实验性）

Tauri 目前没有 OpenHarmony 后端，因此 `openharmony/` 是一个独立的 ArkTS Stage 模型工程：

- `Web` 组件加载 `rawfile/index.html`，完全离线。
- 通过 `javaScriptProxy` 暴露 `window.ohosBridge`，保存时调用 `DocumentViewPicker`，不申请广泛存储权限。
- 文件输入通过 `onShowFileSelector` 接入系统图片选择器。
- `module.json5` 没有声明 `ohos.permission.INTERNET`，从权限层面保证不联网。

构建步骤：

```bash
npm run openharmony:sync   # 生成单文件页面并复制到 rawfile/
```

然后用 DevEco Studio 5.0 或更新版本打开 `openharmony/`，在 `Project Structure > Signing Configs` 配置签名，连接设备或模拟器后运行/构建 HAP。

注意：

- 工程按 API 12（OpenHarmony 5.0）编写；如果本机 SDK 更新，请在 `build-profile.json5` 调整 `compatibleSdkVersion`，并在 `hvigor/hvigor-config.json5` 使用 DevEco 提示的 hvigor 版本。
- `Index.ets` 使用的 `@kit.*` 导入和 `DocumentViewPicker` 属于 API 12+。旧版 OpenHarmony 需要相应调整。
- 当前构建环境未安装 DevEco Studio 与 OpenHarmony SDK，因此此壳尚未实际编译；它属于“尽力支持”，首次用 DevEco 打开时可能需要按 IDE 提示升级工程配置。DevEco Studio 在 Windows 和 macOS 均可使用。

## 发布整理

```bash
npm run package
```

脚本会收集当前平台可用的桌面安装包、便携版、Android APK（若存在）、离线网页与使用说明，写入 `release/`，并生成 `SHA256SUMS.txt`。其他平台的产物可在对应系统上分别运行该命令，或直接从 `src-tauri/target/release/bundle/` 取用。

## 版本对照

本项目验证时使用的工具链：

- Tauri CLI 2.12.4 / Tauri Rust 2.12.5
- Rust 1.98.1
- Android SDK 37 + NDK 29.0.13846066（由 Tauri CLI 2.12.4 要求）
- WebView2 155.0.4283.62

升级 Tauri 后若 Android 构建提示 SDK/NDK 版本不匹配，以 `npx tauri info` 和 CLI 报错中的版本为准。
